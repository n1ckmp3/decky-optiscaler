These headers MUST match the OptiScaler build shipped in bin/. The layout
mirror the ASI uses is generated from Config.h, so a mismatch means the ASI
reads the wrong offsets - it fails its validation checks and stays inert.

menu_common.cpp is vendored for reference only: it is where the in-game
overlay's own live writes live, and it is the authority on which options can
change at runtime and what OptiScaler calls each of them on screen.

wrapped_swapchain.cpp and FG_Hooks.cpp are here for the same reason, for one
claim each. They are the two sides of frame generation, and between them they
are why there are two frame rates to report: the wrapped swapchain times and
counts every frame that reaches the screen (State::presentFrameTime,
State::frameCount), while FGHooks::FGPresent times the game's own presents into
the FidelityFX FG swapchain (State::lastFGFrameTime), which is one per
*rendered* frame. Reading those two slots the wrong way round would swap the
base frame rate with the total, and nothing about the numbers themselves would
look wrong.

FeatureProvider_{Dx11,Dx12,Vk}.cpp are here for one claim too, and it is what
lets the FSR version change without a restart. Each one's ChangeFeature() reads
State::newBackend of Upscaler::Reset - the resting value - as "use whatever
Config holds for *this* API", and sets it back to Reset once a rebuild has
succeeded. That is why changing the version marks every backend changed and
leaves newBackend alone, where the overlay names the current backend explicitly:
it is the same rebuild by a route that cannot pick the wrong graphics API, and
it does not overwrite a real upscaler switch travelling in the same command.

OptiTypes.cpp is the authority on the Upscaler enum: it is where UpscalerToCode
and CodeToUpscaler spell out which backend id each enum value is, which is the
table asi/live.cpp copies for its live switch. v10 replaced 0.9.4's std::string
State::newBackend with this enum, so the ids are no longer what the ASI writes -
the enum value is - and Reset (not the zero-valued XeSS) is what means "use
Config".

unordered_dense.h is the external/unordered_dense submodule at the commit this
tag pins:

    73f3cbb237e84d483afafc743f1f14ec53e12314

That commit is 4.5.0. It matters that it is exactly this version: 5.x replaced
bucket_type::standard with a basic_group bucket and changed the table, and both
would silently move the offsets the ASI mirrors. It is here because
State::changeBackend is one of its tables and the ASI has to find it in memory:
the offsets of its value vector, its load factor and the Upscaler enum declared
straight after it all come from this header's member declaration order. Guessing
them instead is what silently disabled upscaler switching once already, so
asi/live.cpp mirrors the layout and check_asi_backend_layout() in
scripts/selftest.py holds the two together.
